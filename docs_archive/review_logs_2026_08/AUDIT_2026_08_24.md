## 1. Executive verdict

The Aug-23 repair waves were **real but incomplete, and in three cases introduced fresh regressions**. The research/backtest measurement instrument (the thing that decides which strategies deserve capital) survived absorption intact and is now the most trustworthy part of the repo. The live runtime is functional as a *paper simulator* but carries five defects that would be capital-dangerous if LIVE mode were switched on tomorrow:

1. The flagship strategy S01 cannot emit a signal at all (regression from the repair commit itself).
2. Strategy-emitted stop losses never reach orders — the pipeline substitutes its own and mislabels them.
3. In LIVE mode, positions would be recorded with **no broker order ever sent** (the repaired ledger-first path exists but nothing calls it).
4. Tranche exits can double-book an entire position's P&L.
5. Feed-loss "protection" is a logged lie; recovery cannot survive token expiry.

Meanwhile the honest-strategy roster shrank further: of 12 registered strategies, ~8 function live, all on daily bars regardless of design timeframe, with stops overridden, confidence scores 80% fabricated, and HTF filters inert.

**Test suite baseline: 646 passed / 4 failed** (only the known `test_momentum_rsi.py` v2.1-vs-v6.0 noise — which, it turns out, was masking a real regression). Zero network-hanging modules remain.

## 3. CRITICAL — live today

**C1 · S01 MomentumRSI is dead code in production.**
`momentum_rsi.py:188` references `prior_20_high`, undefined since `fef536f` renamed it to `resistance` (only line 147 was updated). NameError swallowed by the internal try → returns None on *every* all-gates-pass frame. Reproduced live with an engineered setup. Masked because `test_momentum_rsi.py` failures were classified as version-drift noise — they were pointing at this.

**C2 · Pipeline discards every strategy-emitted stop loss.**
`pipeline.py:407` reads key `"turtle_sl"` — set by no strategy anywhere (repo-wide grep). Falls back to a generic 10-bar swing stop (:405-416) then stamps the strategy's own `sl_method` label onto it (:445-446). S03's faithful 2N stop, S08's VWAP-box stop, S11's VA-boundary stop, S12's Supertrend stop: none reach orders. Labels lie ("TURTLE_2N" on a STRUCTURE stop).

**C3 · The F3 "binding debate" layer has never executed once.**
`main.py:353` passes `devil_checks_passed=True` (bool); `bull._build_prompt:78` iterates it → TypeError every cycle → caught at `main.py:365-373` → **trade opens anyway without any AI verdict**, `ai_conviction_score`/`debate_summary` never populated. Permanent fail-open by design. Triple-confirmed independently by three reviewers + zero regression tests (census).
*Saving grace:* verdicts DO bind through the older pipeline Gate 6 (`pipeline.py:569-623` returns `SUPERVISOR_DEBATE_VETO` pre-approval). The audit's original claim ("debate ignored") was wrong about Gate 6 but right about everything around it. Quorum (3-of-4, 2-2 revote): still unimplemented repo-wide.

**C4 · LIVE-mode broker dispatch is unreachable.**
F1's ledger-first sequence (reserve ledger → broker dispatch → compensating cancel on failure) is correctly written in `execution/orders.py:143-225` — and has **zero production callers**. `main.py:373` calls `open_paper_trade()` directly. In LIVE mode, positions would be recorded as traded with no broker order ever sent.

**C5 · Tranche full-exit double-counts P&L.**
`orders.py:432`: `int(trade.get("quantity_remaining") or trade.get("quantity") or 1)` — when tranches consume the whole position, `quantity_remaining==0` is falsy → falls through to full original quantity → re-books entire position P&L. Same pattern `tracker.py:376`, `eod.py:155`. Additionally tranche child P&L is written only to `trade_tranches` (`db/trades.py:635-671`) and never rolled into parent `net_pnl`, the capital chain (`eod.py:150`), or risk-engine realized reads.

**C6 · Kill line silently redefined: lifetime-15% → session-15%, armed only in LIVE.**
`emergency_triggers.py:211-215, 498-503, 537`. A slow multi-day bleed can never trip it; in the current paper deployment it is inert entirely. Docstring still says "Lifetime". Ruin protection across days does not exist.

**C7 · Scheduler has no overrun protection.**
All 9 jobs run sequentially inline on the main loop thread (`scheduler_setup.py:119-139`); exception containment only — one hung job (Telegram, DB, WS restart) freezes trailing-SL monitoring indefinitely. Interval jobs anchor to last-fire + 30s loop sleep → "every 1 min" monitor actually fires every ~60–90s; scanner drifts off candle boundaries.

**C8 · Feed-loss protection is theater; recovery can't survive token expiry.**
REST-polling fallback = flag + log line claiming "positions protected", zero implementation (`websocket_supervisor.py:79-84`) — triple-confirmed. `restart_websocket()` reuses startup-era tokens; no re-login anywhere in recovery (`websocket.py:456-498`). After AngelOne daily token rollover, every reconnect attempt fails until manual restart, while open positions are managed off frozen ticks (raw `live_prices` dict bypasses freshness gates: `main.py:59,152`).
